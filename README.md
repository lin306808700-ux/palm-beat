# 掌合节奏 · Palm Beat

用**摄像头识别手掌张合**来玩的音乐节奏游戏。

音符从上方顺着节拍落下，落到发光判定线的瞬间**握一下拳**就能把它击碎。
两条音轨 = 两只手：**左手打左列，右手打右列**，双手同时握拳则双列齐击；
画面里只有一只手时，这只手握拳会同时驱动两列。

> **在线试玩**：https://lin306808700-ux.github.io/palm-beat/ （需要摄像头与网络）

## 运行

需要一个本地 HTTP 服务（用 `file://` 直接打开会因为浏览器限制无法加载模块和摄像头）：

```bash
git clone https://github.com/lin306808700-ux/palm-beat.git
cd palm-beat
python3 -m http.server 8137
# 然后浏览器打开 http://localhost:8137/
```

也可以用任意静态服务器（`npx serve`、`php -S`…）。**手机/平板**同一局域网访问
`http://<电脑IP>:8137` 也行（注意：摄像头在非 https 的非 localhost 域名下会被浏览器拦截）。

> 没有摄像头也能玩：按 `A` / `L` 击打左右列，`空格` 双列齐击。

## 玩法

| 操作 | 效果 |
| --- | --- |
| 握拳（单手） | 击碎该手对应那一列最近的一个音符 |
| 双手同时握拳 | 两列同时判定 |
| 画面里只有一只手 | 握拳同时驱动两列 |
| `A` / `L` / `空格` | 键盘替代方案 |
| `Esc` | 暂停 / 继续 |

- 判定窗口：PERFECT ±75ms、GOOD ±145ms、OK ±200ms，超过就 MISS。
- 分数 = 单note 300/200/100 分 × 连击加成（最高 2 倍）。
- 一曲约 50~75 秒（随难度），有 PERFECT 全连、FULL COMBO、S+ 评级等结算评价。
- **旋律由你演奏**：鼓组 / 贝斯 / 和弦由程序实时合成打底，旋律音只有在你击碎音符的那一下才会响；
  如果完全不理它，会有很轻的提示音托住节奏骨架（可在设置里关掉）。

难度：简单 84 BPM / 普通 100 BPM / 困难 126 BPM，难度同时影响 BPM、音符密度与下落时间。

## 关键实现

### 1. 手掌张合识别

- `MediaPipe HandLandmarker`（本地 `vendor/` 模型，可离线）输出最多两只手的 21 个关键点，
  用**张开度**判断张手 / 握拳：
  `指尖到手腕的距离 ÷ 对应掌指关节到手腕的距离`，取食指 / 中指 / 无名指 / 小指四指平均。
  张手时约 1.7~2.4，握拳时约 1.0~1.2，阈值卡在中间，和手的大小、离镜头远近基本无关。
- 计算用模型输出的 `worldLandmarks`（以手为中心的 3D 米制坐标），
  所以手朝着镜头或侧着摆时也不会像 2D 投影那样把长手指"压短"。
- 握拳分数 = `1 − 张开度`，越过阈值（默认 0.55）**在闭合的瞬间就触发**，不等到重新张开；
  降到阈值的 55% 以下才复位，外加 110ms 冷却，避免抖动重复触发。
- 左右列**不靠模型的左右手标签**，而是用关键点几何位置判断：把画面镜像（照镜子视角）后
  x 更小的那只手 = 屏幕左边的音轨。这样不管摄像头怎么镜像都不会左右颠倒。
  （仍提供「左右手互换」开关兜底。）
- 推理用 GPU delegate，约 30Hz；GPU 不可用时退回 CPU 并自动降频到 ~11Hz + 缩小输入。
  握拳可以保持住，CPU 降频也不容易漏掉动作。

### 2. 计时模型（这个游戏最容易被忽略的部分）

摄像头的画面采集 + 模型推理会让「你真的握拳」和「游戏收到信号」之间差 **100~200ms**。
本项目用一个统一的延迟补偿量 `latency` 处理：

```
判定用时刻 = 收到信号时的歌曲时间 − latency
```

- 因为**视觉、音乐、判定用的是同一个延迟补偿**，所以整体是一致的：音符在判定线上停住等你，
  直到 `latency + 205ms` 才判 MISS——玩家看到的一切都对得上。
- `latency` 由**延迟校准**实测：放 8 拍音乐，跟着每拍握一次拳，取「收到信号时刻 − 音符时刻」的
  中位数（对异常值不敏感）。实测误差中位数可以压到 10ms 级。
- 画面时钟不是直接用 `AudioContext.currentTime`（它按 128/256 采样量化，会 3~6ms 一跳、
  音频线程卡顿时甚至几十毫秒一跳），而是用 `performance.now()` 平滑推进 + 缓慢向音频时钟收敛
  （见 `Game.tickClock()`）。

### 3. 音乐（全程序合成，零音频文件）

`Web Audio` 手写了一套小合成器：底鼓 / 军鼓 / 踩镲（噪声+包络）、锯齿波贝斯、失谐和弦 Pad、
钟琴式击中音，串了混响（程序生成脉冲响应）和延迟，最后过一道限制器。
调度采用经典的 **lookahead 调度器**（每帧把未来 260ms 内的事件写进音频时间轴），
保证节拍由音频时钟驱动、不受主线程卡顿影响。

谱面：`js/chart.js` 用固定 seed 生成，和声走 `Am – F – C – G`，
旋律在 A 小调五声音阶上做有走向的随机游走，重拍强制落在和弦音上 —— 所以每次开的谱不一样但都和谐。
所有音符都严格对齐 16 分音符网格，并按「同轨最小间隔」过滤（握拳最快也要 ~0.3s 一次，超了就删音符）。

## 目录

```
palm-beat/
├── index.html          页面结构（HUD / 各面板）
├── css/style.css       视觉样式
├── assets/             演示视频与封面
├── js/
│   ├── game.js         主程序：状态机、判定、渲染、校准、UI
│   ├── hands.js        摄像头 + HandLandmarker + 握拳状态机
│   ├── chart.js        谱面 / 伴奏事件生成（纯逻辑，可单测）
│   ├── audio.js        实时音乐合成引擎
│   └── util.js         小工具
└── vendor/             MediaPipe 本地依赖（可离线运行）
    ├── vision_bundle.mjs
    ├── wasm/vision_wasm_internal.{js,wasm}
    └── hand_landmarker.task
```

首帧不会联网（`vendor/` 里已放好 tasks-vision 0.10.14 + hand_landmarker 模型）；
若这些文件缺失，会自动回退到 unpkg / Google 模型仓库。

## 设置说明

| 项 | 说明 |
| --- | --- |
| 输入延迟补偿 | 镜头采集 + 识别耗时。**先做「延迟校准」**，之后一般不用手动调 |
| 握拳灵敏度 | 默认 0.55。总是识别不到就调小；老是误触发就调大 |
| 摄像头预览 | 左下角小窗，会画出手的位置和握拳程度环 |
| 旋律提示音 | 关掉后完全靠鼓点找节奏，考验耳朵 |
| 左右手互换 | 万一左右列反了（比如摄像头被镜像过） |
| 纯键盘模式 | 不启用摄像头，用键盘玩 |

## 常见问题

- **识别不到握拳**：手要完整在画面里、掌心或手背朝向镜头，光线亮一点；握的时候稍微握到底。
  还是不行就把「握拳灵敏度」调小。
- **一直 MISS**：先做「延迟校准」。手动调也可以：每次都是「早」（-xx ms）就把补偿调小，
  「晚」（+xx ms）就调大——判定文字下面会显示偏差毫秒数。
- **卡顿**：设置里关掉「摄像头预览」；或在 GPU 不可用的机器上会自动降级到 CPU 推理（更省不了多少，但更稳）。
- **没有声音**：浏览器要求先有一次点击才允许播放音频，点「开始游戏」即可。

## 已验证

- 谱面：三种难度的量化 / 排序 / 同轨最小间隔 / 音高范围均通过自检。
- 音频引擎：离线跑完整首曲子的调度，无异常（事件时间、包络参数均为有限正数）。
- 识别链路：headless Chrome 加载本地 HandLandmarker，模型创建与推理调用无异常；
  合成关键点自检：张手 / 握拳的张开度分离清晰，双手分列、单手双列、左右互换、阈值与冷却均符合预期。
- 判定链路：headless Chrome 实测 —— 键盘输入 19 次判定全 PERFECT，
  模拟握拳事件 23 次判定全 PERFECT，校准可正确反推出人为加入的延迟（实测 24ms，逼近输入时刻的抽样精度）。
